# Brickmart

REST API магазину цегли (`/api/bricks`) на Spring Boot з валідацією та глобальною обробкою помилок.

Запуск тестів: `./mvnw test`

## Покриті сценарії

Модульні тести сервісу (`BrickServiceImplTest`, репозиторій — mock):
- пошук цеглини за id — знайдено / не знайдено (`BrickNotFoundException`);
- список усіх цеглин і фільтр за типом;
- створення нової цеглини;
- оновлення та видалення неіснуючої цеглини — помилка.

Інтеграційні тести контролера (`BrickControllerTest`, `@WebMvcTest` + `MockMvc`):
- `GET` списку, фільтра та однієї цеглини — `200`;
- `POST` валідної цеглини — `201`;
- `GET`/`PUT`/`DELETE` неіснуючої цеглини — `404` з тілом помилки;
- `POST` з порожньою назвою та від'ємною ціною — `400` зі списком `details`;
- некоректний JSON і нечисловий id — `400`.

Усі помилки повертаються в єдиному форматі `ErrorResponse`: `status`, `error`, `message`, `details`.

Приклад відповіді на `POST /api/bricks` з порожньою назвою та від'ємною ціною:

```json
{
  "status": 400,
  "error": "Bad Request",
  "message": "Помилка валідації",
  "details": ["name: назва обов'язкова", "price: ціна має бути додатною"]
}
```
